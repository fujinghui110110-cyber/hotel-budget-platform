# 管理端系统更新

系统代码保存在私有仓库 `fujinghui110110-cyber/hotel-budget-platform`。推送代码不会自动成为可安装的新版本：发布者测试完成后，需发布稳定 GitHub Release，并上传名为 `budget-system-update.zip` 的更新资产。

## 服务器管理员

在运行系统的电脑上，通过固定本机地址 `http://127.0.0.1:8768` 登录管理员账号，进入“系统更新”。首次配置该私有仓库的下载凭据，之后使用“检查更新”和“更新并重启”。凭据应使用 GitHub fine-grained personal access token，仅选择上述单个仓库，仅授予 Contents 的只读权限；不要使用可写仓库或账号级管理权限。凭据只在服务器本机管理员界面配置，不提供给项目用户，不放进代码、发布包或截图。

更新前系统备份数据库和配置，替换程序，执行升级并检查启动状态；失败时恢复旧版本。账号、上传预算、预算数据及本机配置保留，Python 和 LibreOffice 通常无需重复安装。更新期间暂时无法操作，请避开项目集中上传时间。公网服务重启后临时链接可能变化，应重新确认当前链接。

旧版安装包没有“系统更新”入口，不能直接从网页自行获得该功能。第一次请使用含更新功能的新安装包或由维护者进行保留数据的引导升级，先备份原系统目录；不要将空数据库或示例配置覆盖到已有服务器。首次升级完成后可继续通过管理端更新。

每台服务器有独立数据库。更新仅同步程序，不会将另一台电脑的预算或账号同步过来。项目电脑只用浏览器访问时，无需安装或更新程序。

## 发布者

1. 修改 `system_version.json` 中的版本号，例如 `2026.09.11.1`。每次发布必须使用新版本号，不要覆盖已发布版本。
2. 完成测试并提交所有准备发布的代码。构建工具只读取已提交的 Git HEAD；未提交修改不会被打包。
3. 在仓库根目录构建更新包：

```sh
python3 scripts/build_system_release.py --policy docs/refactor/release-policy.json --output /absolute/path/budget-system-update.zip --notes '增加管理端系统更新功能'
```

4. 推送已测试提交，再发布稳定版本（以下为操作示例，不会由构建脚本自动执行）：

```sh
gh release create v2026.09.11.1 /absolute/path/budget-system-update.zip --repo fujinghui110110-cyber/hotel-budget-platform --target <已测试提交的完整SHA> --title '2026.09.11.1' --notes '增加管理端系统更新功能'
```

不要使用 draft 或 prerelease 作为正式更新。GitHub Release 的 tag 使用 `v` 加版本号，资产名称固定为 `budget-system-update.zip`。

更新包根目录包含 `manifest.json`，记录 schema、版本、更新说明，以及每个代码文件的 SHA256。构建器仅选取约定的代码目录、根启动文件与依赖声明，排除环境、数据库、预算附件、安装器和符号链接。离线首次安装包和系统更新包用途不同，不要将数百 MB 的依赖安装包当作更新资产。

### 中断恢复与依赖变更

失败时仅在数据库结构兼容的条件下恢复旧程序；保留当前数据库，不自动用旧备份覆盖升级后数据。语义或结构不兼容时应由维护者处理，不能强制回退。如果断电导致进程中断，在服务器目录执行 `.venv\Scripts\python.exe scripts\system_update.py recover`（Windows），或 `.venv/bin/python scripts/system_update.py recover`（Mac）。备份在 `.runtime/updates/`，恢复完成前不要手动删除此目录。更新后公网链接需要在“公网访问”页重新生成。

发布者修改 `requirements.txt` 时，必须同时提交包含所有直接及间接依赖、精确版本和 SHA256 的 `requirements-update.lock`，覆盖目标 Windows/Mac 对应 wheel。安装强制 `--require-hashes --only-binary=:all:`；缺少锁定文件或哈希不匹配会在停止旧服务前退出。旧 Python 环境保留用于恢复。

不熟悉 GitHub 操作时，请按 [GitHub 更新凭据一步一步操作](GitHub更新凭据一步一步操作.md) 执行。
