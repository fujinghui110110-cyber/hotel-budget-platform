# 在线预算统筹部署方案

## 结论

当前推荐由 Frank 的 Mac 作为唯一业务主机，项目代码放在私有 GitHub 仓库，数据库和各项目上传的预算底稿保存在 Mac 的受控数据目录。项目账号和管理账号都由系统登录控制；GitHub 不保存数据库、上传文件、密码、令牌或备份。

系统默认监听 `127.0.0.1:8768`。现在提供无域名的官方 Cloudflare Quick Tunnel 启动入口，启用前须完成强密码检查；它使用独立安全源站，不改变本机 HTTP 配置。使用和限制见 [公网接入](公网接入.md)。登录后自启仍为可选。

## Mac 主线

### 运行组件

- Python 3.13 和项目 `.venv`；
- Django 应用，由 `scripts/local_server.py` 启动 Gunicorn；
- 一个 `budget_worker`，负责异步上传处理和 LibreOffice 重算；
- LibreOffice；
- SQLite 数据库和本机文件存储。

本机服务用一个 Gunicorn Web 进程加一个 worker，避免 SQLite 和 LibreOffice 任务出现多进程写入冲突。生产配置应设置 `BUDGET_PROCESS_UPLOAD_INLINE=0`。启动、状态和停止统一使用：

```sh
sh scripts/setup_mac.sh
./启动预算统筹系统.command
./启动预算统筹系统.command status
./停止预算统筹系统.command
```

启动器会优先读取项目根目录 `.env.production`，再读取 `.env`。本机正式配置示例是根目录的 `.env.production.example`；不要把示例直接当作已完成配置，先替换 `DJANGO_SECRET_KEY`、数据目录和 LibreOffice 路径。

### 数据目录

建议把数据放在 checkout 之外，例如：

```sh
mkdir -p "$HOME/预算系统数据/storage"
```

本机正式配置应将 `DATABASE_PATH` 指向该目录的 `db.sqlite3`，将 `BUDGET_STORAGE_ROOT` 指向 `storage/`。数据库、原始上传、重算副本、冻结快照、审计记录和备份都属于业务数据，不加入 GitHub。

直接运行 `manage.py` 不会自动读取根目录 `.env`；首次空环境先导出本机正式配置，再执行：

```sh
set -a
. ./.env.production
set +a
.venv/bin/python manage.py migrate --noinput
.venv/bin/python manage.py createsuperuser
```

完成项目账号、项目绑定、预算周期和业务模板登记后，按年度激活最终模板：

```sh
PYTHON_BIN=.venv/bin/python ./deploy/activate_template.sh 2027
```

年度参数必须明确；模板登记命令不会创建演示账号，也不会删除现有数据。

## 预算业务流程

预算周期以 `T` 为中心保存四年口径：`T-3`、`T-2` 为实际，`T-1` 为本年度预测，`T` 为下一年度预算。管理端汇总各项目批准版本，项目端通过自己的账号上传统一模板，系统保留原件、重算副本、来源单元格、公式和哈希。

管理端在 `/management/workpapers/` 导出各项目底稿。页面支持当前批准版本和最新上传版本的原始 XLSX、重算 XLSX，也支持按周期批量下载带来源及 SHA-256 清单的 ZIP。该入口只对管理端开放，导出行为写入审计记录。

## GitHub 边界

私有 GitHub 仓库用于代码协作、部署配置和经过确认的标准模板。以下内容必须留在 Mac 的数据目录或受控备份中：

- `db.sqlite3` 及 SQLite 临时文件；
- `storage/` 中的上传原件、重算文件和冻结产物；
- `.env`、`.env.production`、Cloudflare 凭据和其他秘密；
- 备份、运行日志和真实项目工作簿。

推送前应检查 `git status`、`.gitignore` 和 `.dockerignore`，不要用 `git add .` 把本机数据一起提交。

## 未来固定域名和 HTTPS

有自有域名、Cloudflare 账号和 DNS 管理权限后，再建立命名 Tunnel。示例配置在 [deploy/cloudflared/config.yml.example](../deploy/cloudflared/config.yml.example)，回源地址必须是：

```text
http://127.0.0.1:8768
```

它不会创建隧道，不使用 Quick Tunnel，也不包含可用凭据。外部访问由 Cloudflare 提供 HTTPS，Mac 到 Tunnel 的回源仍为本机 HTTP。完成实际域名和 HTTPS 验收后，才将根 `.env.production` 调整为：

```text
TRUST_PROXY=1
SECURE_SSL_REDIRECT=1
SESSION_COOKIE_SECURE=1
CSRF_COOKIE_SECURE=1
DJANGO_ALLOWED_HOSTS=实际域名
CSRF_TRUSTED_ORIGINS=https://实际域名
```

在此之前保持本机配置的 `TRUST_PROXY=0`、`SECURE_SSL_REDIRECT=0`、`SESSION_COOKIE_SECURE=0` 和 `CSRF_COOKIE_SECURE=0`。不要把“本机能打开”当作“公网已上线”。

## Docker 备用方案

Docker 不是 Mac 主线的启动前置条件。需要隔离运行或迁移到其他主机时，可使用 `Dockerfile` 和 `compose.yaml`，并复制 `deploy/.env.production.example`：

```sh
cp deploy/.env.production.example deploy/.env.production
# 编辑 deploy/.env.production，替换 CHANGE_ME、主机限制和数据配置
docker compose --env-file deploy/.env.production up -d --build web worker
```

该示例默认只映射本机 `127.0.0.1:8000`，与 Mac 原生主线的 `8768` 不同；Docker 备用方案不能反向改变本机主线端口。需要通过 Caddy 提供 HTTPS 时，先完成域名和安全配置，再使用 compose 的 `https` profile。SQLite 场景不要把 Web 服务横向扩展为多个实例。

## 备份和恢复

项目当前没有自动备份脚本。备份时停止服务，完整复制 `DATABASE_PATH` 的 SQLite 文件、`BUDGET_STORAGE_ROOT` 下的全部文件以及每次备份的文件清单和 SHA-256。恢复时先复制到临时目录，执行 `manage.py check`，核对上传版本、文件路径、manifest 和哈希，再由管理者确认后替换工作数据。不要直接覆盖当前目录，也不要删除旧目录。详细步骤见 [docs/RECOVERY.md](RECOVERY.md)。

本方案是单机 MVP，不提供在线热备、跨机房容灾、自动 PITR、对象存储锁定或多人并发冲突解决。需要这些能力时，应先确定正式数据库、对象存储和备份策略，再进行独立迁移设计。
