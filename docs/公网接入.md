# 电脑作为预算服务器的公网访问

采用成熟的 [Cloudflare Tunnel 官方项目](https://github.com/cloudflare/cloudflared)，不开放路由器端口，不把数据库传到 GitHub。电脑持续联网、本机服务和隧道进程运行时，其他人可通过生成的 HTTPS 链接访问登录页面。运行期间通过 macOS 自带 caffeinate 防止系统空闲休眠，停止公网进程即释放，不修改永久电源设置。手动休眠、合盖、关机或断网仍会中断访问。

当前无域名使用 [Quick Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。地址随机生成，重启隧道会变化。官方明确用于测试/开发、无可用性承诺、最多 200 个并发请求，不支持 SSE；适合目前三项目试用，不能承诺稳定生产入口。要长期固定地址，应使用已有 `deploy/cloudflared/config.yml.example` 配置命名隧道，需 Cloudflare 账号及域名。

## 使用

启动前先把所有有效账号的示例密码改成独立强密码。公网认证要求至少 12 字符，并拒绝常见、纯数字或与用户名相似的口令。脚本也会阻止已知示例弱密码。不要将密码放入链接或分享日志。

双击项目根目录 `启动公网访问.command`，或执行：

```sh
.venv/bin/python scripts/public_access.py check
.venv/bin/python scripts/public_access.py start
.venv/bin/python scripts/public_access.py status
```

复制输出的 `https://…trycloudflare.com` 地址给项目使用。第一次启动可能需要一分钟；查看 status 取得地址。`running` 仅表示进程在运行，还需实际用该地址登录并确认上传页面可用，才能判断当前网络下公网已连通。

双击 `关闭公网访问.command` 或执行 `.venv/bin/python scripts/public_access.py stop`；再执行 status 确认 running 为 false。本机入口继续可用。本功能未安装系统自启，电脑重启后需重新启动并获取新链接。

## 隔离与日志

本机 HTTP `127.0.0.1:8768` 保留原配置。公网独立 Gunicorn 只监听 `127.0.0.1:8769`，只接受此次生成的精确主机名与 CSRF 来源；禁用 DEBUG，强制 HTTPS 和 Secure Cookie，打开 PUBLIC_ACCESS 登录防护。cloudflared 通过出站 HTTP/2 连接，不把 8768/8769 绑定到外网。使用同一数据库和上传任务队列，start 会先启动既有本机服务器及 worker。

日志：`logs/public-supervisor.log`、`logs/public-tunnel.log`、`logs/public-web.log`。连接失败检查网络能否访问 Cloudflare Tunnel 服务；防火墙可能阻止出站 7844。不要通过禁用证书验证、通配 hosts 或开放数据库端口解决连接失败。

公网独立密钥保存在 `.runtime/public-secret-key`，权限 600；不要提交 `.runtime`、日志、数据库、原始预算文件。会话与本机独立，公网需重新登录。

- 解压安装：`.runtime/bin/cloudflared`

更新时从官方 release 下载匹配架构的文件，核对 release 的 SHA256 digest 后解压；不用第三方镜像、随机安装脚本或复制隧道核心代码。脚本禁用运行中自动更新，使版本可追溯。

## 本机网络连通性验证（2026-09-10）

使用仅返回 `budget connectivity check` 的临时 `127.0.0.1:8779` 服务建立官方隧道。实际通过 HTTPS 请求得到 HTTP 200、`Server: cloudflare`、26 字节预期正文，并在本机服务观察到对应 GET；证明当时出站隧道及公网回源可用。测试后已关闭隧道和临时服务，测试地址不可作为预算系统入口。正式系统的账号登录与上传仍须在启动正式入口后独立验收。
